# NixOS configuration

NixOS + Home Manager configuration.

## Hosts

| Host | Machine | Rebuild |
| --- | --- | --- |
| `nixos-test` | QEMU/KVM VM in virt-manager | `sudo nixos-rebuild switch --flake .#nixos-test` |
| `nixos-usb` | External USB SSD booted on the laptop, see [docs/install-usb.md](docs/install-usb.md) | `sudo nixos-rebuild switch --flake .#nixos-usb` |
| `nixos-laptop` | Laptop internal NVMe, encrypted with a separate `/home`, Secure Boot and TPM unlocking, see [docs/install-laptop.md](docs/install-laptop.md) | `sudo nixos-rebuild switch --flake .#nixos-laptop` |

On an installed system, `nh os switch` rebuilds the current host: each host is
named after its hostname, and nh already knows where this repository lives.
`nh clean` runs weekly and keeps at least the last five generations.

## Layout

    flake.nix         hosts, the laptop module list, and the host/username
                      passed to every module
    modules/          the system: one file per concern
    home/             the desktop account, one file per concern
    hosts/<name>/     boot, hardware, screen and anything else per machine

`modules/user.nix` declares the account and wires Home Manager to `home/`.
The account name is written once, in `flake.nix`, and reaches every module
through `specialArgs`.

## Network mirrors

The default `nixpkgs` input comes from the TUNA git mirror and the binary cache
from the SJTU mirror, for connections from China. When a VPN is active, use the upstream GitHub input and
cache instead:

```bash
sudo nixos-rebuild switch --flake .#nixos-laptop \
  --override-input nixpkgs github:NixOS/nixpkgs/nixos-unstable \
  --option substituters https://cache.nixos.org
```

Without these extra options, the Chinese mirrors are used.

## Hyprland

This configuration targets current Hyprland (0.55+) and uses its Lua
configuration format through Home Manager.

The generated file is:

    ~/.config/hypr/hyprland.lua

The old `hyprland.conf` format is intentionally not used.

## VM

Before the first rebuild, make sure the repository contains the hardware
configuration generated by this VM:

```bash
cp /etc/nixos/hardware-configuration.nix hosts/nixos-test/
```

Then:

```bash
nix flake check
sudo nixos-rebuild switch --flake .#nixos-test
```

Reboot afterwards:

```bash
sudo reboot
```

## os-tracker

The presence daemon comes from the `os-tracker` flake input and runs as a
systemd user service, enabled in `home/os-tracker.nix`. Its token is read at
service start from a file this repository never contains:

```bash
mkdir -p ~/.config/os-tracker
printf 'OS_TRACKER_TOKEN=%s\n' "<token>" > ~/.config/os-tracker/token.env
chmod 600 ~/.config/os-tracker/token.env
```

Upgrade it with `nix flake update os-tracker` and a rebuild, and check it with
`systemctl --user status os-tracker`.

Do not commit passwords, SSH private keys, API tokens or cloud credentials.

## CI and updates

Pull requests and pushes run `nix flake check --no-build`, Statix, Deadnix and
formatting. This evaluates every host without building a complete system
closure, keeping CI fast and within hosted-runner limits. The weekly update
workflow refreshes `flake.lock` and opens a pull request only after the same
evaluation and static audits pass.

Dependabot is enabled for GitHub Actions. Dependabot does not support Nix
flakes or `flake.lock`, so Nix inputs are updated by `.github/workflows/update.yml`.
